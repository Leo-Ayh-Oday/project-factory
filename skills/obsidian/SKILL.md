# /obsidian — Save to Obsidian Knowledge Base

将会话产出（技术方案、bug 分析、决策记录、日报）写入 Obsidian vault，自动归类到多层文件夹，并建立与已有笔记的 wiki 链接。

## Setup

### 1. 配置 Vault 路径

在 `~/.claude/settings.json` 的 `env` 中设置（或 export 环境变量）：

```json
{
  "env": {
    "OBSIDIAN_VAULT_PATH": "/home/user/obsidian-vault"
  }
}
```

```bash
export OBSIDIAN_VAULT_PATH="/path/to/your/vault"
```

如果未配置，skill 启动时提示用户设置。

### 2. 可选：自定义分类规则

在 vault 根目录创建 `.claude-categories.json`：

```json
{
  "bug_analysis": "bugs/{project}/{date}",
  "tech_spec": "知识库/{domain}/{topic}",
  "daily_digest": "日记/{YYYY-MM}",
  "decision": "项目/{project}/decisions",
  "learning": "知识库/{domain}/learnings",
  "project_doc": "项目/{project}"
}
```

未配置时使用默认规则（见 Phase 2）。

## 与 Superpowers 联动

```
/execute-plan → /obsidian 自动分类存档
                                        ↓
                                   /daily-digest 引用归档链接
```

本 skill 是**流水线终端**——把一天的产出固化到第二大脑。在 `/daily-digest` 之前跑，日报里可以附上 vault 笔记链接。

## Phased Workflow

### Phase 1: Load Config

1. 读 `$OBSIDIAN_VAULT_PATH`（env var 或 settings.json env block）
2. 如果 vault 根目录有 `.claude-categories.json`，加载自定义分类规则
3. 验证 vault 路径存在且可写
4. 扫描 vault 顶层目录结构作为分类参考

若 vault 路径未配置 → 输出配置说明并停止。

### Phase 2: Classify Content

根据内容类型自动确定目标路径。优先级：**用户指定 > 自定义规则 > 默认规则 > AI 推断**。

**默认分类规则：**

| 产出类型 | 检测信号 | 默认路径 |
|----------|----------|----------|
| Bug 分析 | 来自 `/learn-from-bugs`，含 root_cause | `bugs/{project}/{YYYY-MM}/` |
| 技术方案 | 含架构/设计/方案/API 设计等关键词 | `知识库/{domain}/` |
| 日报 | 来自 `/daily-digest`，含概览/变更/决策 | `日记/{YYYY-MM}/` |
| 决策记录 | 路径/库/框架选型相关 | `项目/{project}/decisions/` |
| 学习笔记 | 踩坑/经验/教训/convention | `知识库/{domain}/learnings/` |
| 项目文档 | 项目启动/阶段总结/release | `项目/{project}/` |
| 通用笔记 | 以上均不匹配 | `inbox/`（待整理） |

**领域检测（domain）：**
- `AI技术` — LLM/Agent/RAG/提示词/MCP
- `前端` — React/Vue/CSS/animation
- `后端` — API/数据库/部署
- `工具` — CLI/脚本/自动化
- `通用` — fallback

**项目检测（project）：**
- 从当前工作目录名推断
- 用户也可显式指定：`/obsidian --project 酒包ERP`

### Phase 3: Generate Note

每篇笔记按以下模板生成：

```markdown
---
date: {YYYY-MM-DD}
source: {来源 skill 或会话 ID}
category: {分类}
project: {项目名}
tags: [tag1, tag2]
---

# {标题}

## 概述
{1-2 句总结}

## 内容
{主体内容，保持原有格式}

## 相关笔记
- [[{相关笔记1}]] — {关系说明}
- [[{相关笔记2}]] — {关系说明}

---
> Generated by Claude Code `/obsidian` on {date}
> Session: {session_id}
```

### Phase 4: Handle Multi-Level Folders

目标路径支持嵌套（如 `项目/酒包ERP/3D渲染/UV展开/`）。自动创建不存在的中间目录。

文件夹命名规则：
- 中文优先，技术术语保留英文（如 `bugs/`, `decisions/`）
- 日期用 `YYYY-MM` 或 `YYYY-MM-DD` 格式
- 无空格，用 `-` 连词

### Phase 5: Build Wiki Links

搜索 vault 中已有笔记，建立双向链接：

1. 用笔记标题/文件名搜索 vault 中的相关笔记
2. 关键词匹配：项目名、技术术语、文件名
3. 每篇新笔记包含 2-5 个 `[[wiki-link]]`
4. 不创建死链接（除非用户要求）

### Phase 6: Confirm & Write

写入前展示：

```
📁 目标路径: 项目/酒包ERP/bugs/2026-06/UV展开精度bug分析.md
🏷️ 分类: Bug 分析
🔗 相关笔记: [[3D渲染管线]], [[buglog分析]], [[ERP架构]]
📝 内容长度: ~2,300 chars

写入? (y/n)
```

用户确认后写入。

## Rules

- **DO** 写入前展示路径和分类，等用户确认
- **DO** 用 `$OBSIDIAN_VAULT_PATH` —— 绝不用硬编码路径
- **DO** 自动创建中间目录
- **DO** wiki-link 只链接 vault 中已有的笔记
- **DO** 优先中文文件夹名，技术术语保留英文
- **DO** 未配置 vault 路径时输出清晰的 setup 指引
- **DON'T** 在未确认时写入文件
- **DON'T** 覆盖已有笔记 —— 同名时追加 `-2`, `-3`
- **DON'T** 链接不存在的笔记（除非用户明确要求占位）
- **DON'T** 假设 vault 结构 —— 先扫描再分类
- **DON'T** 硬编码任何个人路径或用户名
